# 消化一份新的來源資料

## 步驟

1. 確認輸入是什麼型態：貼上的文字、檔案路徑、還是需要透過 MCP 連接器（Google Doc / GitHub / Slack / Jira / 網頁）去查詢的連結。如果是連結但看起來需要登入或權限，如實回報而不是假裝讀到了內容。

2. 把原始資料交給 `intake-analyst` subagent 處理，讓它在獨立 context 裡做逐句抽取，避免把長逐字稿整份塞進主對話。

3. subagent 回傳的「事實清單」直接呈現給使用者，附上出處。**不要在這一步做範圍判斷、feature 歸屬判斷、優先順序建議，或決定這是不是要做的事**——這些是 `scope-doc` 的工作，建議使用者接著用 `scope-doc`。

4. 如果一次要消化多份文件（例如同一個 initiative 的三份不同來源），對每份各自呼叫一次 `intake-analyst`，最後才彙整成單一清單，並在「相互矛盾之處」欄位特別標注跨文件的不一致。

## 何時不要用這個技能

- 使用者已經有明確結論、只是要你幫忙寫成任務或程式碼 —— 直接做，不需要先跑一次抽取。
- 資料是程式碼本身（不是需求/決策類文件）—— 用一般的程式碼閱讀方式，不套用這個流程。
