# 把待釐清項目轉成問回上游的訊息

## 步驟

1. 掃描 `project-state/decisions.md`、`backlog.md`、`risks.md`，找出所有 `[待釐清]` 與 `[有衝突]` 的項目。
2. 把每一項改寫成**具體、可回答**的問題，而不是把原本模糊的描述直接複製過去當問題。

   不好的問法：「這個功能的範圍是什麼？」（太空泛，對方也不知道從何答起）
   好的問法：「範圍是否包含批次匯出？如果包含，CSV 和 Excel 兩種格式都要在第一版做，還是可以先做一種？」

3. `[有衝突]` 的項目，兩邊來源的說法都要列出來，明確請對方裁定，**不要暗示哪一邊比較可能是對的**。
4. 每個問題附上簡短背景（為什麼會產生這個疑問、來源是什麼），讓對方不用回頭翻文件也能直接回答。
5. 依照「會不會卡住接下來的開發」排序，最急迫的放最前面，不要照檔案裡原本的順序照抄。
6. 如果環境支援訊息草擬工具，用它產生 Slack 或 email 版本；不支援的話直接輸出 Markdown 格式的問題清單。

## 硬性規則

- 不要自己猜答案、幫忙填上「應該是這樣吧」——這些項目會被列進這裡，就是因為你不該猜
- 不要為了讓清單看起來精簡，把本質不同的疑慮合併成一個問題
- 每個問題都要可以被單獨回答，不要一題裡塞兩件不相關的事

## 輸出格式

```markdown
## 待確認事項（依急迫程度排序）

1. **[問題]**
   背景：為什麼會有這個疑問，來源是什麼
   （若為衝突）來源 A 說：... ；來源 B 說：...
```

## 完成後

提醒使用者：「這些問題送出去之後，對方的回覆記得用 `ingest-doc` 重新消化一次，並註明是回覆哪一則問題」——這樣回覆才會正確地成為下一輪迴圈的新資訊，而不是又變成一份孤立、沒有上下文的紀錄。
